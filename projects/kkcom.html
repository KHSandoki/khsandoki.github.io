KKCOM

A serial terminal built for the specific misery of hardware bring-up: the commands you send fifty times a day get a button, and the whole thing ships as one file.

The itch

Bringing up a microcontroller means staring at a serial port for hours. You send the same handful of probe commands over and over — dump this register, toggle that pin, read the version string — and general-purpose terminals make you retype every one of them, every time, from scratch.

KKCOM is the terminal I wanted during that loop. It is a rewrite in modern C++ of an older tool of mine, with Dear ImGui for the interface because immediate-mode UI suits a program whose entire job is redrawing a stream of incoming bytes.

What it does

  • Custom command tabs. Save the commands for a given board as a set, load them back next session. Each one is a button. This is the whole reason the program exists.
  • Toggle send for commands you fire repeatedly — one click on, one click off, rather than hunting through scrollback for the last time you typed it.
  • Multiple COM ports with configurable baud rates and live receive.

Two builds from one tree

The CMake setup produces two meaningfully different binaries:

  • Debug keeps a console window attached and logs verbosely — when the thing you are debugging is a serial protocol, you need to see the bytes underneath the UI.
  • Release is a clean GUI subsystem build with no console, and with the application icon and splash screen compiled in as Win32 resources.

That second point matters more than it sounds. The release build is a single .exe with no loose asset files and no installer. You drop it on a USB stick, run it on whatever machine happens to be next to the bench, and it works — which is exactly the situation a bring-up tool needs to survive.
